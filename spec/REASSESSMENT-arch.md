# Specification for Proposal: REASSESSMENT-arch

## Architecture
The Configuration Platform now has three complete in-memory layers: domain models (11 dataclasses + exceptions), abstract repository interfaces (10 ABCs), service layer (10 services with cross-entity referential guards), and REST API (10 route modules + shared api-core). All 13 platform boundaries from the authoritative architecture are respected and no boundaries have been violated. The platform cannot yet be deployed: four infrastructure gaps remain. Gap 1 — no concrete PostgreSQL repository implementations exist; the abstract interfaces have no backing store. Gap 2 — the User domain model lacks password_hash, which is required for JWT credential verification (CVP-009), and this field must be excluded from all API serializers to prevent credential leakage. Gap 3 — no composition root wires repositories into services into the Flask application. Gap 4 — no authentication layer guards the API endpoints. The resolution sequence is: (1) db-core shared module provides PostgreSQL connection primitives reusable by all 13 future platforms; (2) Configuration Platform PostgreSQL repository layer implements all 10 ABCs, adds User.password_hash to the domain model and Alembic schema, and adds find_by_username to UserRepository; (3) a composition root wires the full dependency graph and provides a Gunicorn-compatible entry point with a /health endpoint; (4) a shared auth module provides JWT issuance and bcrypt-based credential verification, with middleware guarding all protected routes. No new platform is introduced. All work is within the Configuration Platform domain and the shared layer (db-core, auth). After CVP-009, the Configuration Platform will be the first fully deployable platform in the system, capable of serving ConfigurationObject contracts to downstream platforms.

- CVP-008 depends on CVP-007 — concrete repos must exist before the composition root can wire dependencies
- CVP-009 depends on CVP-008 — running server is required for end-to-end auth integration tests
- CVP-007 must update User domain model (add password_hash) and update _serializers.py (exclude password_hash) in the same task to avoid a window where credentials could be exposed

## Acceptance Criteria
- After CVP-006: db-core is importable; get_session() context manager correctly commits and rolls back PostgreSQL transactions; psycopg2-binary is in pyproject.toml
- After CVP-007: All 10 Configuration Platform repository ABCs have working PostgreSQL implementations; User.password_hash exists in domain model and Alembic schema; password_hash is absent from all API response payloads; Alembic migration 001 creates the full schema from scratch
- After CVP-008: The Configuration Platform Flask app starts from DATABASE_URL env var; all 10 entity endpoints function end-to-end against a real PostgreSQL instance; GET /health returns 200
- After CVP-009: All protected endpoints reject unauthenticated requests with 401; valid JWT grants access; password verification uses bcrypt; auth module has no platform imports
